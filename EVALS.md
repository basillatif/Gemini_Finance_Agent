# Evals

Two live runs on 2026-10-26: a **baseline** on the code as it was, and an
**after** run once the top failure was fixed. Gemini 2.5 Flash on Vertex AI,
ADK 2.11.0, judge model Gemini 2.5 Flash with 3 samples.

## What's tested

20 cases / 21 turns in `revenue_agent/evals/revenue_agent.evalset.json`,
generated by `build_evalset.py`:

| Kind | Cases |
|---|---|
| Single-period lookups | revenue by region, total, units by channel, segment last month, calendar year 2025, combined filters |
| Comparisons | West YoY, region YoY, quarter over quarter, East margin YoY |
| Trends | AI Add-ons monthly (trailing 12), quarterly (all data) |
| Relative dates | last quarter, last month, trailing 12, year to date |
| Multi-turn | channel breakdown → "how does that compare to last year?" |
| Should decline or redirect | Q1 2027 (no data), top-10 customers, forecast, "Northeast" region, edit the warehouse |

**The answer key is independent of the agent.** `build_evalset.py`
recomputes every expected figure from `revenue_daily.csv` with its own
aggregation code; it never calls `get_revenue`.

### Metrics

| Metric | How it scores | Pass rule |
|---|---|---|
| `tool_args_match` (custom) | The expected tool calls appear in order with the expected arguments. Extra calls are allowed; empty-string arguments are ignored. | Every turn |
| `required_figures` (custom) | Every figure in the answer key appears in the answer (±$1 for rounding, ±0.05 on percentages) | Every figure |
| `grounded_figures` (custom) | Every $, %, or count in the answer matches a number in that turn's tool results or the question. This is how "never invent numbers" is checked. | Every figure |
| `rubric_based_final_response_quality_v1` (ADK judge) | Gemini scores the answer against 1–2 case-specific rubrics ("says Northeast is not an available region") | ≥ 0.8 |

A case passes only if **all** metrics pass on **every** turn. Before the
live runs, the deterministic metrics were checked offline against six answers
saved from earlier `adk web` sessions. `grounded_figures` correctly flagged
the two answers from the old code where the model did its own arithmetic
($580,503, 25.42%, and a wrong total of $8,180,691), and passed the current
code's answer to the same question.

## Failure patterns

### 1. Relative period the calendar didn't cover (baseline, fixed)

`year_to_date`: *"What's our revenue year to date?"*

The agent called `get_reporting_calendar`, found no year-to-date period, and
replied only: *"I can only provide data up to September 30, 2026."* It didn't
answer, and it made no `get_revenue` call. That failed three metrics.

Root cause: two contradictions.
- The calendar tool's docstring told the model to call it for "this year",
  but the tool returned no such period.
- Prompt rule 2 said to refuse anything outside the data window, and "year to
  date" on 2026-10-26 runs past the last day of data (2026-09-30), so the
  model treated it as out of range.

**Fix** (`agent.py`):
- Added `year_to_date`, `same_period_last_year`, and `last_year` periods to
  the calendar, capped at the end of the data.
- Rule 1 now lists these phrases.
- Rule 2 now says to answer the covered part of a partly-covered period and
  say where the data stops.

**After:** passes all four metrics with the expected call
`get_revenue(group_by="none", start_date="2026-01-01", end_date="2026-09-30")`.

### 2. Inconsistent number formatting (baseline, fixed in prompt)

Not counted as a failure, but visible in baseline answers:
- unit counts without separators ("8003", "15323")
- margins written as "63%" in one place and "63.1%" in another
- table and date-range lines on answers that only declined a request

**Fix:** rule 5 now specifies units with separators, percentages to one
decimal, and no table on refusals. `grounded_figures` was also extended to
check bare counts like "8003", which it previously skipped. That was a gap
in the metric, not the agent.

### 3. Rubric metric not scoring (eval setup, fixed)

In the baseline, the judge metric errored on every case with "Rubrics are
required" and never called the judge. ADK's
`rubric_based_final_response_quality_v1` only accepts rubrics tagged
`type: "FINAL_RESPONSE_QUALITY"` and silently drops the rest.
`build_evalset.py` now sets the tag. All 20 cases were judged in the after
run.

### 4. Answer less complete than the key (after, open)

`east_margin_yoy`: *"Did gross margin improve in the East last quarter
compared with the same quarter last year?"*

The tool call was correct and the answer was right: *"Yes … improved by 0.2
percentage points."* But this time it showed only the change, not the two
margins (63.0% vs 62.8%). In the baseline run, the same case showed both and
passed. So this is **run-to-run variance**, not a regression from the
fixes. The judge passed it, because the rubric only asks for a yes/no.

**Not fixed, on purpose.** Loosening the answer key to accept "0.2 pts" alone
would hide a real quality issue: finance users want the levels, not just the
delta. Options:
- add to rule 5: "for comparisons, show both periods' values and the change"
- run each case 3× and report a pass rate per case, since single runs this
  close to 100% can't tell variance from regressions

## Caveats

- **n = 1 run per configuration.** At 19/20, one flaky case moves the
  headline by 5 points. Treat the numbers as "no systematic failures," not
  as a precise rate.
- The judge passed 20/20; it's lenient on cases where the deterministic
  metrics are strict, which is the intended split.
- The cases use one synthetic dataset and were written by the same person
  who built the agent. Real user questions would add phrasings this set
  doesn't cover (fiscal years, "H1", "MTD", typos in region names).

## Reproduce

Run from `revenue_agent/`. These make live Gemini + BigQuery calls; each run
is about 90k agent tokens plus the judge.

Rebuild the eval set after editing cases:
```bash
../.venv/bin/python evals/build_evalset.py
```

Run the evals:
```bash
PYTHONPATH=. ../.venv/bin/adk eval revenue_agent evals/revenue_agent.evalset.json --config_file_path evals/test_config.json
```

Print the tables and failure details for the latest run:
```bash
../.venv/bin/python evals/summarize.py
```
